# Production-readiness audit — 2026-08-13

Four adversarial reviews run in parallel against the real code and a live
Supabase stack: **data/server**, **iOS feature completeness**, **the engine**,
**monetization/compliance**. Every finding below was evidenced with a file
reference, a query against the running database, or an executed probe —
nothing here is inferred from documentation.

The blunt summary: the engine and the course catalog are genuinely strong.
The **claims layer** was not. The app asserted things to users that the code
did not do, the docs asserted things the app did not have, and the
subscription sold three features of which one did not exist and none were
gated.

---

## Fixed in this pass

### Critical

| # | Finding | Evidence | Fix |
|---|---|---|---|
| 1 | **Finished runs were destroyed, while the UI said they were saved.** `RunResultView` displayed "Your run is safely stored and will upload when you're connected"; the outcome lived only in a SwiftUI `@State` and was deallocated on dismiss. No persistence existed anywhere in the app. | Repo-wide grep for `FileManager`/`SwiftData`/`.write(to` over `App/Sources` returned zero hits | Built `PendingRun` / `RunStore` / `UploadQueue` in the Kit: enqueue **before** the first network call, delete only on server acknowledgement, crash-in-flight recovery, corruption quarantine, capped exponential backoff. Wired at launch and on every foreground. 10 tests. |
| 2 | **A remote-triggered fleet crash.** `ScoreBreakdown.finalScore` used a `precondition` on weight validity and `AppEnvironment` decoded the server's scoring config raw instead of via `ScoringConfig.load`. One malformed row in `scoring_configs` would SIGILL every client the instant a drive finished. | Probe reproduced the trap through the normal pipeline | Weights fall back to v1 defaults; the client validates the config at the boundary. Regression tests added. |
| 3 | **`score-run` authenticated nobody and checked no ownership.** Any user could POST another user's `runId` and receive their score, confidence and anti-cheat integrity flags. | Handler read `runId` from the body and never inspected `Authorization` | Caller resolved from JWT via the auth server; service-role callers stay unrestricted as internal machinery; other users' runs return 404. |
| 4 | **Storage path traversal into a service-role read.** `telemetry.storage_path` was client-supplied, unvalidated, and interpolated into a service-role storage URL — RLS bypassed. | A `../../..` payload was accepted live (HTTP 201) | Validated in `score-run` **and** by a database trigger requiring the run owner's own prefix. |
| 5 | **The app was unusable in a Release build.** `CourseDetailView`'s only data path was inside `#if DEBUG`, so the primary CTA led to a permanent spinner with an empty title. | `CourseDetailView.load` fell off the end with `course` nil | Real server fetch (`course_route` RPC) plus an explicit failure state with retry. |
| 6 | **The drive screen could trap a driver.** With location denied or no GPS, the pre-run states contained no interactive element, no back button, and never advanced. Force-quit was the only exit. | Every state transition ran only from the `.gps` branch; `authorizationStatus` was never read | Permission checked up front with a Settings link, a 45-second no-fix watchdog that fails honestly, and Cancel always present before a run starts. |

### High

| # | Finding | Fix |
|---|---|---|
| 7 | **A single NaN GPS fix voided an entire run** — NaN passes every comparison, so it was kept and then poisoned the teleport gate for all later samples: a valid 20-minute drive reported 0 m and 0 gates. | Finiteness gate added ahead of all others; regression test. |
| 8 | **Leaderboards were structurally wrong.** `rank` is computed per course, the query had no course filter, so every course's #1 appeared together, all reading "rank 1". | Scoped to today's challenge course, named on screen; Global/Country/Friends now actually re-query; real error state; pull to refresh. |
| 9 | **The leaderboard claimed a fact about the world when it had failed to ask** — network failure and an empty board both rendered "No verified runs yet". | Distinct failure state with retry. |
| 10 | **The subscription conferred nothing.** `hasPro()` had zero call sites; no feature was gated. The paywall sold ghost racing (not implemented), custom courses (no UI) and analytics (no UI). | `DailyRunAllowance` — 3 scored runs/day free, unlimited with Pro — enforced on the course screen, with the upgrade prompt placed at the moment of intent. Paywall now sells only what exists. |
| 11 | **No `Transaction.updates` observer.** Renewals, refunds, Ask-to-Buy approvals, promo codes and other-device purchases were invisible; unverified purchases were silently swallowed and never finished. | Observer started at launch; purchase outcomes are now distinct (`cancelled` / `pending` / `unverified` / `failed`) with honest copy; restore reports what it found. |
| 12 | **"Delete account" was an empty closure** — an App Store 5.1.1(v) hard rejection, with no server-side path either. | Confirmed flow calling a new `delete_my_account()` RPC, plus a storage delete policy so raw telemetry blobs are erasable (they previously survived deletion with no index back to them). |
| 13 | **Ghost privacy never persisted.** The picker wrote a local `@AppStorage` key nothing read; the server enforces from `profiles.ghost_visibility`. Choosing "Nobody" kept serving your ghost to strangers. | Reads and writes the server column, with an honest error if it can't. |

### Medium

- `runs.status` was client-writable with no guard — a client PATCHed a run to `scored` with a 1-second 10,000-point body (HTTP 204, verified in the database). A transition guard now permits only the `recording → uploaded` move the upload flow legitimately needs.
- `course_checkpoints` RLS lacked the `friends` branch `courses` has, so a friends-visibility course was listed but had **zero gates** — visible and undriveable.
- "Participants today" counted any run row, and clients can insert run rows, so the number Today's Challenge promises is real was inflatable. Verified runs only now.
- The pre-flight checklist was a static picture ("Waiting for GPS lock" forever, "Mount your phone" pre-ticked). It now reflects real session state.
- "TRY AGAIN" did not try again — it dismissed to the course screen. It now re-drives the course (and honestly reads "DONE" in mock mode, where the synthetic stream is single-use).
- The required subscription disclosure was the least legible text in the app (3.63:1, below the 4.5:1 minimum) and lacked Terms/Privacy links.

## Known gaps — deliberately NOT fixed here, ranked

These are honest gaps, not lies, and each is now either unadvertised or
explicitly labelled in-app.

**Closed since this audit (2026-08-13, same day):**

1. ✅ **Sign in with Apple** — hashed-nonce challenge, Keychain session, token refresh, and signing in flushes the offline queue. Optional: the app drives and queues signed out.
2. ✅ **Ghost racing** — the course screen fetches the best ghost the privacy rules allow and races it; the live gap readout is no longer dead code.
3. ✅ **Run history and real records** — Your runs lists every drive; Profile's rating/wins/top-10 come from the server.
4. ✅ **Friends** — send / accept / decline / remove all work.
5. ✅ **App Store Server Notifications** — fail-closed webhook (JWS + pinned Apple root CA).

**Still open:**

1. **Stale scoring jobs are never re-driven.** The sweeper flips `processing → pending` but nothing re-invokes `score-run`, so a crashed job sits forever. `scoring_jobs.attempts` is never incremented either.
2. **No crash-safe in-flight recorder.** `DriveSession` holds the only copy of raw telemetry for the whole drive; a mid-drive crash still loses it. The queue protects the *finished* run only.
3. **`DriveSession` has no timeout or sample cap** — parked in `.ready`, it accumulates IMU at ~50 Hz (~150 MB/hour) until iOS jetsams the app.
4. **Universal links declared but never handled** — `smooooth.app/challenge/<CODE>` opens the app and drops the code.
5. **Zero accessibility modifiers** app-wide, 23 fixed `.font(.system(size:))` that ignore Dynamic Type, and several tap targets under 44pt (including "End run", used while driving).
6. **Golden vectors never exercise the compliance/speeding path** (`speedLimits` is hard-coded empty), so xval passes while that whole branch is cross-validated by nothing. The TS ghost port is covered by nothing at all.
7. **Degenerate runs still show flattering provisional scores** — a run with no GPS scores 6,500; looping the course 10× shows a provisional 10,000. Verdicts correctly mark them invalid so they cannot rank, but the number shown to the user is misleading.

## What the audit confirmed is genuinely strong

- **The course catalog holds up under attack.** 397 courses / 30 countries exactly as documented; zero duplicate names; `distance_meters` within 1% of measured geometry on every course; all benchmarks between 54 and 88 km/h; every course has exactly 5 gates lying **exactly** on the route at 0/25/50/75/100%; no ocean jumps (max vertex gap 351 m).
- **The trust boundary holds where it matters most.** Clients cannot write `score` or `verification` even on their own runs (HTTP 403, column-level grants). Cross-user reads of runs and telemetry envelopes correctly return empty. `leaderboard_entries`, `subscriptions` and `scoring_jobs` writes are all refused.
- **Anti-cheat is real.** Teleport runs, parked runs and 10× loops all trip the correct flags and land `invalid`.
- **Determinism holds.** `tools/xval.sh` passes: all 12 golden profiles reproduce byte-exactly across Swift and TypeScript.
- **`apply_run_result`** is a single transaction with `SELECT … FOR UPDATE`, best-score-only upserts, and idempotency.
- **The palette is accessible** — measured contrast 5.3–6.4:1 for secondary text across all three surfaces; the one failure (the paywall disclosure) is fixed.

durability (restart, crash-in-flight, corruption, backoff, FIFO, re-entrancy),
